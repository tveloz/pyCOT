## IMPORTANT scalability constraint (read before running big sweeps)
`fusigenic_inflow_search.py`'s exhaustive per-species sweep re-runs the FULL
ERC→hierarchy→synergy→complementarity→EPM pipeline once per candidate. That's
~0.05-0.1s/candidate on e_coli_core (fine, exhaustive over ~65 candidates in
~5s) but the pre-EPM stages alone take ~50s on iAF1260-scale networks (1500+
ERCs) -- confirmed earlier this session. An exhaustive sweep over ~1400
candidate species at iAF1260 scale would take on the order of 50000s (~14h)
and is NOT feasible. For genome-scale networks: ALWAYS pass a curated
candidate list (e.g. just the known trace metals) or `--max-candidates` with
a small number (20-30), never run the bare exhaustive default.

  doesn't add NEW reachability for those two, only for Fe-S cluster, which
  neither side can make alone). Worth being explicit about this distinction
  in the report: "biologically plausible transporter" != "structurally
  load-bearing for EPM reachability" -- these can and do diverge, and the
  knockout tool is what tells them apart.
- [t6] **Real mitochondrial-type result (surprising, real, worth reporting
  honestly):** knocking out XPORT_PYR alone OR XPORT_ATP alone gives the
  SAME result either way: hybrid EPM count goes UP slightly (27->28) with
  UNCHANGED mean/max size (28.2/30). Neither individual interface reaction
  is uniquely load-bearing in this real genome-scale case -- the real
  network's own internal redundancy (multiple real routes connecting
  ATP/pyruvate pools -- ADK1, PYK, PPS, etc., all still present in both
  host and symbiont) means either single transporter alone is already
  sufficient to achieve full hybridisation; they are functionally
  redundant with EACH OTHER at the EPM-reachability level, unlike the toy
  model's XPORT_FES which has no redundant alternative route. This is a
  genuine, real disanalogy between the deliberately-minimal toy model and
  real metabolic network redundancy, and is itself a useful methodological
  lesson: real networks may need MORE interface reactions knocked out
  simultaneously (or a genuinely irreplaceable one, like the toy model's
  Fe-S cluster) before any single-knockout shows the "load-bearing" signal.
  Log: `outputs/mito_knockout.log`.
